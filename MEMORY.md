# Budget Tracking App Memory

Last updated: 2026-09-17

## Current Production

- Production is Cloudflare Workers at `https://app.formedlicensing.workers.dev`.
- Vercel is not used for this app anymore. Older Vercel release notes are historical only.
- Normal production release path: `npm run cf:build`, then `npm run cf:deploy`, then live smoke checks on the Cloudflare Workers URL.
- `wrangler` OAuth tokens expire and cannot refresh non-interactively. When a deploy fails asking for `CLOUDFLARE_API_TOKEN`, the fix is `npx wrangler login`, which completes on its own if Matt is already signed in to Cloudflare in his browser. Being signed in to the Cloudflare dashboard in Chrome is not by itself CLI auth.
- `npx wrangler rollback` is denied by the Claude Code permission classifier, so a bad deploy cannot be rolled back automatically. The only recovery path is fixing forward: diagnose with `npx wrangler tail --format json`, rebuild, and redeploy. A Bash permission rule for `npx wrangler rollback` would close this gap if Matt wants automatic rollback available.

## Durable Patterns

- `docs/mockups/` holds external design handoffs verbatim, including Claude Design's prototype runtime `support.js`. That folder is in the eslint ignore list because the runtime is reference material, not app code — it throws deprecated-React and `module`-assignment errors otherwise. Add future handoffs there rather than leaving them in Downloads.
- A rail or panel that is a CSS grid **and** stretches to the viewport height (`self-stretch`, or a flex child in a full-height row) will stretch its own grid rows to fill the leftover space, because `align-content` defaults to `stretch`. On the Licensing Summary rail this rendered the action buttons at 57px instead of the 42px the design asked for, and pushed the sections apart — it reads as "the buttons are too big" when the real cause is the container. `content-start` on the grid pins rows to their own height. Check this before re-tuning any size in a full-height rail.
- The Licensing Summary's needs-attention list is deliberately the *design prototype's* two rules — titles with no confirmed rate, and the one installment above 4x the average — not the old `buildNeedsAttentionItems`. Matt chose this on 2026-09-16. `attention-model.ts` and the `dismissNeedsAttentionItem` action were deleted the same day. **The `attention_dismissals` table is deliberately left in the database**: it holds 12 rows of Matt's own "Mark complete" clicks from July–August 2026 on FY2027 roadmap and review items, and on 2026-09-16 he chose to keep them rather than drop the table. Nothing reads them. Do not propose dropping it again unless he raises it.
- Provider colour overrides survived the removal of the pie chart: the picker now lives in a `<details>` under the provider ranking in "Where the money goes", and those colours paint the ranking bars. Without that move, `provider_color_overrides` rows would still be stored and rendered but no longer editable anywhere.

- Planning and review data should persist server-side through Supabase-backed server actions, not local-only React state.
- For `contentEditable` notes fields, do not rewrite `innerHTML` during `onInput`; let the browser accept text while focused and linkify URLs on blur or external updates.
- Review Notes and Comparable Content behavior is combined in the visible Notes editor in Content Review.
- Content Review URLs should be clickable inside the editable textbox, not moved to a separate preview control.
- Content Review notes are rich text stored as sanitised HTML in the same `notes` text column. No Supabase migration was needed, and legacy plain-text notes still render because both formats are detected on read.
- Notes markup is sanitised in the editor and again in the server action, against a small tag allowlist. Inline-CSS formatting is converted to tags, because that is what Word and Google Docs pastes produce.
- Anything that consumes notes as plain text, such as the Send to Roadmap handoff, must flatten the markup first.
- Deploying to Cloudflare without committing leaves production running code that exists nowhere else. This happened before 2026-08-31: the full "Proposed Yearly Rate" rename was live while `main` had only the queue column header. Always commit and push what you deploy.
- Content Review's review_status pipeline (as of 2026-09-14) is: not_started, on_the_radar, in_progress, blocked, acquisition_target, contracted, rejected. "Approved" no longer exists — it was split into acquisition_target (team wants it, no contract yet) and contracted (deal signed). "Send to roadmap" only fires at contracted, and requires minutes to be filled in first.
- The Roadmap's Mix rankings must always be computed from the category-filtered items, never from the Mix-filtered ones. Ranking the already-filtered list collapses each card to the single row that is selected, which removes the only way to unpick it. `buildRoadmapMix` in `roadmap-mix.ts` takes the base list for this reason, and a test in `roadmap-timeline.test.tsx` guards it.
- Roadmap status colours reuse the existing tone lines (`ROADMAP_STATUS_META` in `planning-constants.ts`): planned=slate, scheduled=blue, in_progress=purple, blocked=red, released=green, so statuses and category swatches stay one colour system. The board labels `released` as "Live"; the edit form still calls it "Released".
- `minutes` (total runtime for the whole piece, never broken into episodes) and `budget_source` are now expected on every piece of content — Licensing, Roadmap items, Content Review items, and Ongoing Series all carry both. The columns are DB-nullable (no way to backfill historical minutes), but every add/edit form treats them as required going forward.
- Never symlink `node_modules` from the main checkout into a git worktree or any other copy of this repo before running `npm run cf:build`. Run `npm ci` in that copy instead. A symlink makes `opennextjs-cloudflare` emit a worker that fails at runtime with `Dynamic require of "/.next/server/middleware-manifest.json" is not supported`, so `/login` and the server-rendered pages return 500 while the static demo pages still serve. The build reports success and `npm test`/`npm run build` pass, so only a live smoke check catches it. This broke production on 2026-09-15.
- When the working tree is dirty with a concurrent session's in-progress work, do not deploy the tree as-is and do not touch their files. Deploy from a clean copy: `git worktree add --detach <scratch path> <pushed commit>`, copy `.env.local` in, `npm ci`, then `cf:build` and `cf:deploy` from there, and `git worktree prune` afterwards. Production then runs exactly what is on `origin/main`. This satisfies the never-deploy-what-isn't-committed rule without blocking on the other session.
- Running `npm run build` in the project folder overwrites `.next` and breaks any dev server already running from it, including another session's — chunk requests start returning 404/500 and the page never hydrates, so clicks silently do nothing. Port 5173 is also frequently already held by another session. To verify UI changes without disturbing it, start a second dev server on another port (a temporary extra entry in `.claude/launch.json`, removed afterwards).
- Content Review layout intent, so a future session does not undo it while "fixing" the layout: the left rail runs the full viewport height; the selected-review panel ends with its content rather than stretching to the bottom of the page; the panel's left edge is a drag handle; and the All reviews lane opens with every status group collapsed, as a table of contents.

- A plain `npm run build` leaves `.next` in a state that `npm run cf:build` trips on: it fails with `Cannot find module './611.js'` or ``File `.next/types/app/<route>/page.ts` not found`` even though the code is fine. Fix: `rm -rf .next .open-next`, then run `cf:build` — expect to run it twice, because the first pass regenerates `.next/types` and the type check in that same pass is what fails. Do not go looking for a compile error in the diff.
- Concurrent sessions in this folder contaminate more than deploys. While another session is mid-edit, `npm test` can fail on assertions that match the committed source, and `git log`/`HEAD`/`git status` can read inconsistently between calls. Confirm any failure twice, and check `git status` for another session's modified files, before reporting a regression to Matt. On 2026-09-15 a phantom `content-review-workspace.test.tsx` failure was reported to him this way; the suite was green (241/241). A concurrent session can also **stash the whole working tree**, taking your in-progress edits with it — on 2026-09-16 two finished edits silently reverted mid-session and turned up in `stash@{0}` alongside another session's `licensing-summary` work. If your own edits vanish from the tree, check `git stash list` before re-doing them; `git stash pop` restores both sets.
- A mixed-size or mixed-case display style (letters rendered at different sizes, e.g. a larger first letter per word) cannot be applied directly inside a live `<input>` — the browser computes the text caret's position from the actual characters in the field, so if the visible rendering differs from that (different glyph widths per letter), the caret drifts out of sync with what's on screen while typing. Fix: swap between a plain, uniformly-styled input while focused (for editing) and a styled read-only overlay while blurred (for display) — never render both, and never style the live input's characters unevenly. Used for the Content Review title field's all-caps-with-larger-first-letter treatment.
- A `display: flex` container can silently collapse whitespace-only text nodes between inline `<span>` children — words rendered with no space between them ("OLDSTONEABBEY" instead of "OLD STONE ABBEY") when the Content Review title overlay was first built with a flex wrapper. Fix: don't rely on flex plus bare text-node spaces for multi-word inline styling; use normal block flow (matching the underlying input's own box model) instead.
- Alignment classes in the Content Review queue grid must go on the cell element itself, not on an inner `inline-flex` button. `SortHeader` had `justify-end` on its button, where it silently did nothing — the header never moved. The cell (`<span role="columnheader">`) carries `flex` plus the `justify-*` class; the button just holds the text.
- When resizing a transparent logo or icon, flood the RGB channel with the target colour across the whole canvas and resize **only the alpha channel**. Resizing RGBA directly makes LANCZOS pull the transparent pixels' black RGB into the glyph edges, producing a dark halo that is invisible against a light background and obvious against a dark one. The first Formed logo shipped on 2026-09-16 had this halo; it was caught only by compositing the PNG over navy by hand, because a browser screenshot at normal size hides it.
- In a protected page, `await requireInternalSession()` **before** starting any Supabase query. Never put the session check and a Supabase call in the same `Promise.all`: `Promise.all` settles on the *first* rejection, so when a signed-out request coincides with a Supabase failure the Supabase error beats the `NEXT_REDIRECT` and surfaces as a 500 instead of redirecting to `/login`. `/login` and the `/demo/*` pages are immune only because they make no Supabase call. All four protected pages (`/dashboard`, `/content-review`, `/roadmap`, `/coproduction`) shipped with this shape until 2026-09-17; the session check is local HMAC work with no round trip, so awaiting it first costs nothing. Guarded by `src/app/protected-page-auth-gate.test.ts`, which forces Supabase to reject first and fails on the old code for all four pages. A healthy Supabase makes the smoke checks pass either way, so green smoke checks do not prove this is fixed — the test does.
- **`content-review-workspace.test.tsx` has two known, accepted failures as of 2026-09-17**, so the suite baseline is **241 passing / 2 failing**, not green. The two are "selects a priority from the rail list" and "sorts the queue by column header and cycles back to the manual order". Cause: `title-caps.tsx` renders each word as two spans (larger first letter + uppercase remainder), so no single DOM node contains a whole title and `screen.getAllByText(/Zebra|Alpha/)` and `getByRole("button", { name: "Alpha Mission" })` can no longer match. The app itself is correct — the tests are stale, not a defect. Matt was offered the fix on 2026-09-17 and declined; do not "helpfully" fix them or re-report them as a new regression unless he raises it. These are **not** the 2026-09-15 phantom failure: confirmed twice on a clean tree with an empty `git stash list`, with the mechanism traced to `title-caps.tsx`.
